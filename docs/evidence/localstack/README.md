# Local stack: the vault against the real MPC nodes and a real EVM node

Everything below ran on one machine against:

- a single-validator `neard` localnet,
- the real NEAR MPC signer contract (`v1.signer-prod.testnet` code, version 3.18.0), initialized with two real `mpc-node` 3.18.0 participants in non-TEE mode (`[tee.authority] type = "local"`, as the near/mpc localnet guide does),
- domains 0 (Secp256k1 Sign), 1 (Ed25519 Sign), 2 (BLS12-381 CKD) and 3 (Secp256k1 ForeignTx), all four keys generated by the nodes' own DKG,
- `anvil` with chain id 84532, configured in both nodes as their `Base` foreign chain and voted into the contract's provider whitelist by both nodes.

No signature, attestation, CKD response or receipt in this directory was produced by a mock. The only stand-ins are the ones the localnet itself is: one NEAR validator instead of a network, anvil instead of op-geth/Base Sepolia, and local (mock) TEE attestations for the nodes, exactly as the near/mpc localnet does it.

## What surprised me (read this first)

Status on the final build (ceedcd4, runs `*-final`): findings 3 and 4 are fixed in the contract and verified below; finding 1 is addressed in the relayer (it settles only the attempt that is final on Base), which this harness does not drive, so the vault-side behaviour of an early settle (timeout, heir Pending) is unchanged and re-measured.

1. **A settle sent before finality is not refused, it is abandoned.** The leader node retries a not-yet-final `verify_foreign_transaction` about once a second (10 tries, then 5 by a failover leader, all within about 15 s: `MAX_ATTEMPTS_PER_REQUEST_AS_LEADER = 10` in `crates/node/src/requests/queue.rs`), then nobody looks at it again until the 200-block yield timeout returns `Request has timed out`. Measured: finality arriving 4 s after the request -> attested; 30 s after -> timed out although the request was still pending on chain. On Base Sepolia finality is many minutes after inclusion, so whoever calls `settle` must first see `eth_getBlockByNumber("finalized") >= receipt.blockNumber` themselves. An early settle costs only gas; the heir stays Pending and settle can be called again.
2. **v2 is bricked by a single MPC config vote.** Raising `sign_call_gas_attachment_requirement_tera_gas` above 150 (two node votes plus `submit_contract_update`, no code change) makes every `sign` and `verify_foreign_transaction` the v2 vault sends panic `Provided gas is lower than required`, because v2 attaches a constant 150 Tgas. v3's GasWeight fixes this up to what the caller attaches: at 300 Tgas prepaid `sign` gets 193.4 Tgas (survives 190, fails 200); neard 2.14 accepts up to 1000 Tgas per call, and at 1000 Tgas prepaid `sign` got 543 Tgas and survived a 500 Tgas requirement (7Ua97eX).
3. **The re-price path keeps the tip fixed, and geth-family pools would refuse the replacement.** Every attempt uses tip = `min(max_priority_fee_per_gas, max_fee)`, so a re-priced attempt raises only the fee cap. anvil accepts that as a same-nonce replacement (`anvil-replacement-rule.txt`). geth's txpool (and so op-geth on Base) requires both the fee cap and the tip to rise by its price bump (10%) to replace a pending tx, so on Base the re-price would come back `replacement transaction underpriced` while attempt 0 is still in the sequencer's pool. This is from geth's txpool code (`core/txpool/legacypool/list.go`, `list.Add` rejects a replacement unless both `GasFeeCap` and `GasTipCap` clear the bump); I had no op-geth here to run it. anvil also differs the other way: it refuses a tx whose max fee is below the current base fee at submission, and evicts a pending one once the base fee rises above it, where geth would keep it queued.
4. **A callback that runs out of storage strands the payout.** `begin_attempt` adds 104 bytes and `on_signed` 205. With 206 free bytes the MPC network signed, `on_signed` failed `LackBalanceForState`, its writes rolled back and the payout kept `signing: true`. A plain NEAR transfer restores the balance but not the payout: in v2 every later `request_signature` on it is refused `signature already in flight`, forever. v3 build XtF7uF5 recovered it after its 3600 s lease (measured). On build 7Ua97eX the lease is 86400 s, and the new `submit_signature` does not help here: given the real MPC signature (still readable on chain as the return value of the signer's yield callback) it refuses `attempt still awaits its callback`, because the stranded attempt is exactly the in-flight one it excludes. So a storage-starved callback costs that payout a day on the current build.
5. **The callbacks are nowhere near their gas.** Worst measured `on_signed` 4.71 Tgas and `on_settled` 4.61 Tgas, at 16 heirs, 32 witnesses, 8 signers and a 41-attempt payout (v3 bounds). v2 has no bound on signers: 120 signers cost about 4.05 Tgas, so 60 Tgas needs thousands.
6. **Two node votes can switch Base off.** Changing the Base provider entry to a host the nodes do not run makes them re-register an empty chain set within seconds; `settle` then fails immediately with `Requested foreign chain, Base, is not available.` It is reversible by the same vote and leaves the vault intact. 3.18.0 has no vote that deletes a chain.
7. **A reorged-out payout recovers by itself.** After `anvil_reorg` the tx left anvil's pool, the vault address nonce went back to 0, the network answered `transaction was not found` (no attestation), and the identical signed tx, rebuilt from vault state, landed again with the same hash and then settled.
8. Operational: a new MPC participant's (mock) attestation is only stored after someone pays `prepay_attestation_storage` for it (20 milliNEAR); until then `vote_new_parameters` fails `Invalid TEE Remote Attestation`.

# final build (fresh up.sh); PRIORITY_WEI sets a 0.1 gwei configured tip so the tip scaling is visible

scripts/localstack/down.sh

`up.sh` writes all keys (localnet only) to `~/development/near-hackathon-research/localstack-run/state.json` and process logs to `.../localstack-run/logs/`. The harness takes the vault wasm path as its first argument, so a rebuilt contract runs with the same commands. `faults.mjs` takes a comma list of faults as its third argument (`gasconfig,providers,reshare,storage,signers,upgrade-same,upgrade-break`); `upgrade-break` replaces the signer contract and leaves the stack unusable, so run `up.sh` again afterwards.

Files under `scripts/localstack/`: `up.sh`, `down.sh`, `bootstrap.mjs` (accounts, signer deploy, init, domain and provider votes), `lifecycle.mjs`, `faults.mjs`, and `lib/` (a minimal borsh NEAR client signing with `node:crypto`, the evidence recorder, anvil RPC, vault deploy). Broadcasting reuses `relay/base.mjs` (`assembleSignedTx` checks the payload hash, the recovered signer and the tx hash before anything is sent); the CKD unwrap and pairing check reuse `agent/seal.mjs`.

## How finality is driven on anvil

anvil 1.7.1 answers `eth_getBlockByNumber("finalized")` with `latest - 2 * slots_in_an_epoch` and `"safe"` with `latest - slots_in_an_epoch` (default 32 slots, so 64 blocks). `up.sh` starts it with `--slots-in-an-epoch 2 --no-mining`, so finalized is exactly `latest - 4` and nothing is mined unless the harness calls `anvil_mine`. Probe (`latest 10 / safe 8 / finalized 6`, then `17 / 15 / 13`) was run before writing the harness. The MPC node's EVM inspector (`crates/foreign-chain-inspector/src/evm/inspector.rs`) asks for the `finalized` head and refuses with `NotFinalized` while it is below the receipt's block, then checks the receipt's block hash against `eth_getBlockByNumber(n)` and refuses `status != 1` as `TransactionFailed`.

Evidence layout: `events.jsonl` is the ordered log (one line per tx, EVM observation, view and assertion); every NEAR tx has a numbered JSON file with its hash, decoded result, per-receipt gas (`receipts[].method`, `tgas`, `prepaid_gas`, `status`) and the full `send_tx` response; `evm-*` files hold raw anvil responses; `state-*` files hold `get_state` snapshots; `nodelog-*` files are the MPC node log lines for that window.

## Not done, and why

- **No op-geth / Base node.** Everything EVM-side is anvil 1.7.1. Its mempool rules differ from geth's (finding 3), and its `finalized` tag is a fixed lag, not L1 finality. I did not install geth to check finding 3 by running it.
- **No agent payout path.** `propose_payout` needs a decision signed by a registered NEAR AI enclave key; there is no enclave on the localnet and registering a key I generate would be a mock. All payouts used `execute_fallback`. The `register_signer` state-growth probes use random addresses and are only about state size.
- **Day-long waits not waited.** On 7Ua97eX, the retry after `reopen_reverted` (86400 s) and the sign lease (86400 s) were only shown to refuse; their expiry was not waited out. The 3600 s lease of the earlier build XtF7uF5 was waited out (`faults-v3-XtF7uF5-storage/`).
- **"Base removed"**: no such vote exists in 3.18.0; replaced by a provider change that makes Base unavailable.
- **Resharing on 7Ua97eX** not repeated (keys are an MPC property and were shown unchanged on two reshares).
- The v2 `signers` probe ran on-chain up to the 16 gwei re-price; its settle step failed in my harness (nonce 1 broadcast before nonce 0), fixed for the v3 runs.
- Throughout, anvil was funded from its own unlocked dev account (`eth_sendTransaction`), and base fees were set with `anvil_setNextBlockBaseFeePerGas`; those are chain setup, not vault behaviour.
